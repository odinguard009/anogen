This file is the single source of truth for ANY AI that operates this repo (Claude, ChatGPT/Codex, Gemini, etc.). CLAUDE.md only points here. Read engine/sop.md and engine/PORTABILITY.md as well.

Owner: Odin (Indonesian; not a coder). Talk to him in Indonesian: concise, direct, no flattery, no fabrication, phone-friendly. Stories are written in English at LEARNER LEVEL (see story/style/profile.md, section LEVEL). The owner never touches code: you run every command, commit and push.

Words used here (LOCKED SETTING 13: agents are never spawned; the orchestrator performs each role itself): "agent" = the role being performed (originally a separate AI run (own context) that does one job and returns a report. "strong tier" / "standard tier" = model classes mapped to real models in engine/models.json. The "orchestrator" = the AI the owner talks to; it runs scripts, spawns agents, commits, sends files, and never writes chapters itself.

## Layout (one folder per novel)
- Engine (shared by all novels): tools/ (scripts, 0 tokens), roles/ (instructions per role), engine/ (sop.md, PORTABILITY.md, models.json, locked-settings.md, writer/critic/rewrite prompts, prices.json), templates/novel/ (empty starting folder for a new novel), docs/, tests/.
- Each novel lives ONLY in `novels/<slug>/`: story/ (brief, style, bible, outline, inbox), chapters/ (chapter-NNN.md), ops/ (engine.json, schedule.json, run-log.md, scores.csv, decisions.md, blocked.md, rewrite-queue.md, usage.jsonl), out/ (EPUBs, reading page), archive/. `novels/ACTIVE` names the active novel.
- PATH CONVENTION: in every prompt and role, `story/`, `chapters/`, `ops/` and `out/` mean the folders INSIDE THE ACTIVE NOVEL (`novels/<slug>/...`); `engine/`, `tools/`, `roles/` are engine files. All tools resolve this by themselves (`python3 tools/novel.py status` shows the active novel). At the start of each role stage, apply this: "Active novel folder: novels/<slug>/ (story/, chapters/, ops/, out/ are inside it). Read and write nothing in any other novel."
- Style lives only in the novel's story/style/profile.md (swappable per novel). The engine is genre-neutral.
- Novels never share canon, names, style or state. Never copy anything from one novel into another unless the owner orders it.

## Commands (owner's Indonesian phrases)
- "mulai cerita baru" (+ title, seed or "bebas"): `python3 tools/novel.py new <slug> --title "..."` (slug = lowercase title with hyphens; add `--style-from <slug>` only if the owner asks to reuse a style) creates novels/<slug>/ from the neutral template and makes it active. The owner usually brainstorms first: record his answers in story/brief.md and story/inbox.md. Then the development editor (strong tier) builds the story pack and plans arc 1 (roles/development-editor.md); commit and push; do not write chapters unless asked.
- "daftar novel": `python3 tools/novel.py list`. "pilih novel X" / "ganti ke X": `python3 tools/novel.py use <slug>`. All other commands act on the active novel; name the novel in your replies.
- "tulis bab berikutnya", "kerjakan N bab" (`engine_state.py batch-start --mode n --target N`), "generate 1 arc maksimal N bab" (development editor plans the arc: `engine_state.py arc-plan K --start S --end E --max N`; then `batch-start --mode arc --arc K --max N`): run the Production flow.
- "ide: ..." / "belokkan arah: ...": `python3 tools/inbox.py add "text"`; confirm in one line.
- "laporan": `python3 tools/status.py`; 3-6 lines.
- "hidupkan jadwal" / "matikan jadwal": `python3 tools/schedule.py enable|disable` (scheduler tool of the host AI; tell the owner what is unverified).
- "lanjutkan": FIRST check ops/rewrite-queue.md: if any range is not DONE, run the rewrite for the first such range (prompt engine/rewrite-prompt.md, one agent, standard tier, under the lock); keep going batch after batch with no per-session limit (owner order 2026-11-25). Otherwise: `engine_state.py batch-resume`; retry items in ops/blocked.md first; `check_chapter.py` on the highest chapter and `precheck.py`; `lock.py status`; `engine_state.py next`; continue the Production flow. If critic_pending exists, run the critic before more writing.

## Production flow (strictly sequential: ONE role at a time, never parallel; NO SUB-AGENTS, see locked setting 13: wherever a step below says 'spawn ONE agent', the orchestrator runs that role itself, inline)
0. `python3 tools/engine_state.py next` -> `writer_range` (at most 5 chapters; clamped before any existing chapter, see `gap_note`), `critic_pending` (only set when a critic range of 10 chapters is due; `critic_waiting` otherwise), `critic_changed_after_review`, `audit_with_critic`, `audit_due_at`. If `lock.py status` is busy, start no role stage.
1. If the outline lacks the chapters or story/inbox.md has ideas: development editor first (strong tier, under the lock).
2. WRITER: `python3 tools/lock.py acquire write --owner writer`; run the writer stage yourself (standard tier). Prompt = engine/batch-writer-prompt.md + "Your range: chapters A-B." + the commit trailer lines (see engine/PORTABILITY.md). When it ends: `lock.py release write --owner writer`; log its usage with `python3 tools/usage_log.py add --role writer --range A-B ...` (token counts only if the host reports them; otherwise omit, never guess); verify with `git log`, `git status`, `python3 tools/verify_batch.py A-B`; if it died (quota): `engine_state.py batch-stop --reason "..."`, commit what exists, report.
3. CRITIC (+ AUDIT), once per 10 chapters (owner order 2026-11-25: critic per 10 chapters, i.e. after every second writer batch; replaces the earlier "after each 5-chapter batch"): run it only when `critic_pending` is set (it is, when 10 chapters are ready, when a batch ends, or at arc end). First `python3 tools/verify_batch.py A-B` (deterministic go/no-go; fix or retry the writer on problems). Then `lock.py acquire critic --owner critic`; run the critic stage yourself (strong tier). Prompt = engine/batch-critic-prompt.md + "Your range: A-B." (use `critic_pending`; add "Audit duty: yes" when `audit_with_critic` or `audit_due_at` is set). The critic runs `tools/prepass.py` first. Then `lock.py release critic --owner critic`; only if `git log` shows the "critic pass chapters A-B" commit: `engine_state.py mark critic B`; if an audit commit exists: `engine_state.py mark audit B`. Chapters changed after their review (`critic_changed_after_review` = `rereview_pending`) are an editorial task that blocks `writer_range` until done: run the critic stage (strong tier, under the lock) with "Re-review only: X, Y" (no full 10-chapter pass needed; if `critic_pending` is also set, add them to that run), then record exactly those chapters with `engine_state.py rereview X Y` (it updates hashes only for the chapters listed; `mark critic` never blesses edited chapters).
4. `python3 tools/save.py "..."` for anything left; `engine_state.py next`.
5. Reading page: `python3 tools/build_reading_page.py` and publish out/reading-page.html with the host AI's page tool; record the URL in ops/reading-page.txt. If blocked, log it in ops/blocked.md.
6. NO SESSION LIMIT (owner order 2026-11-25): keep running batches until the target or `continue` is false, a quota/limit is hit, or a STOP-list case happens. State survives in ops/engine.json. Report only at the end, in 3-6 lines.
Arc end: when `next` says the arc is fully written, run the critic on `critic_pending` (all of it still unreviewed), then `arc-complete K`, `build_epub.py --arc K`, save, and send out/arc-K.epub to the owner.
All roles run as sequential stages inside the one main session (locked setting 13). The same session writes and critiques, so the critic stage relies on tools/prepass.py, tools/verify_batch.py and the written checklists.
